# Excalidraw for TOS 7

A [Excalidraw](https://github.com/excalidraw/excalidraw) whiteboard packaged as a **TOS 7 Deb application**.
Opens inside the TOS desktop as an iframe — sketch diagrams, flowcharts and ideas with a
hand-drawn feel. Drawings stay on your NAS.

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](https://github.com/excalidraw/excalidraw/blob/master/LICENSE)

---

## Install

Download the `.deb` from [Releases](../../releases), then pick one method:

**Method 1 — App Center (recommended)**

```
TOS Desktop → App Center → Manual Install → select excalidraw_x86_64.deb
```

**Method 2 — SSH / dpkg**

```bash
sudo dpkg -i excalidraw_x86_64.deb
systemctl status excalidraw
```

**Method 3 — the TOS developer tool** (see [tos-app-pkg-tools](https://github.com/terramaster-tos/tos-app-pkg-tools))

```bash
python -m tool.tos_tool install excalidraw_x86_64.deb -H <nas-ip> -u <user> -p <password>
```

After installing, **Excalidraw** appears in the App Center.

## What it does

| | |
|---|---|
| **Subtype** | WebUI Internal Open (`type: iframe`) |
| **Back end** | Python 3, HTTP over Unix Socket at `/var/api/excalidraw.sock` |
| **Front end** | Official Excalidraw web build, served from `/usr/local/excalidraw/webui/` |
| **Data** | Stays on the NAS — drawings live in browser local storage and export to file |
| **Telemetry** | None (upstream analytics stripped at build time) |
| **Languages** | UI follows the browser locale; App Center metadata ships zh-cn / zh-hk / en-us / fr-fr |

### Features

- Hand-drawn style shapes, arrows, free-draw, text, sticky notes
- Export to PNG / SVG / Excalidraw JSON
- Dark mode
- Works fully offline — no external CDN, no fonts fetched from the internet

## Package layout

TOS 7 requires application metadata inside the deb payload at `usr/local/<appid>/`
(see the official *TOS 7 Application Development Guide* §8.2).

```
pkg/
├── DEBIAN/
│   ├── control
│   ├── postinst          # create user/group, unpack webui, start service
│   ├── prerm
│   └── postrm
└── usr/local/excalidraw/
    ├── config.ini        # App Center registration (read by the platform parser)
    ├── excalidraw.lang   # i18n, INI sections; filename MUST equal <id>.lang
    ├── excalidraw.env    # environment file for systemd
    ├── bin/excalidraw    # executable entry point
    ├── init.d/excalidraw.service       # systemd unit (no Restart=, platform owns it)
    ├── images/icons/excalidraw.svg     # icon, path MUST match config.ini.icon
    ├── lib/excalidraw_tos/server.py    # backend
    └── webui.bz2         # front end (generated by build.sh, not tracked)
```

`config.ini` key fields:

```json
{
  "id": "excalidraw",
  "system_id": "excalidraw",
  "package": "excalidraw",
  "user": "excalidraw",
  "publisher": "TerraMasterCommunity",
  "path": "/excalidraw/",
  "icon": "/images/icons/excalidraw.svg",
  "type": "iframe",
  "application_type": "deb"
}
```

> `publisher` must not contain spaces — the platform uses it to create a Linux user.

## Build from source

```bash
# Full build: clones upstream Excalidraw, builds the UI, assembles the deb
./build.sh --with-frontend

# Or, if you already have a webui.bz2 in pkg/usr/local/excalidraw/
./build.sh
```

Requirements: `dpkg-deb`, `python3`, `git`, plus Node 24 + Yarn 1.22 for `--with-frontend`.

Output: `dist/excalidraw_x86_64.deb`

### Post-processing the upstream build

`scripts/postprocess.py` adapts the stock Excalidraw web build for TOS. Five changes, each
needed only because the app runs as a **same-origin iframe behind a sub-path**:

| # | Change | Why |
|---|---|---|
| 1 | Strip the SimpleAnalytics script | It reports embed events to an external CDN |
| 2 | `/assets/…` → `./assets/…` | Assets must resolve under `/excalidraw/` |
| 3 | `EXCALIDRAW_ASSET_PATH` → runtime absolute URL | Upstream's `normalizeBaseUrl()` resolves `"./"` against the origin root, so fonts 404 under a sub-path and the app crashes |
| 4 | Relax the self-embedding guard | Upstream treats a **same-origin** parent as self-embedding and renders `I'm not a pretzel!`; TOS iframes are always same-origin |
| 5 | Drop the PWA service worker and source maps | A cached SW serves stale builds inside the iframe; maps add 16 MB |

Issues 3 and 4 are invisible when opening the page directly — they only appear once the app is
served from `/excalidraw/` inside the TOS desktop.

## Runtime footprint

| Path | Content |
|---|---|
| `/usr/local/excalidraw/` | Program files (platform maps this to `/Volume<N>/@apps/excalidraw/`) |
| `/usr/local/excalidraw/webui/` | Unpacked front end |
| `/usr/local/excalidraw/data`, `logs` | Application state and logs |
| `/var/api/excalidraw.sock` | Unix socket for the platform proxy (mode 0660) |

Removing the package keeps `data/` and `logs/`; only `purge` deletes them.
User drawings are never stored server-side, so nothing is lost on uninstall.

## Troubleshooting

```bash
systemctl status excalidraw          # is it running?
journalctl -u excalidraw -n 100      # why did it fail?
ls -l /var/api/excalidraw.sock       # did the socket get created?
cat /usr/local/excalidraw/logs/postinst-diagnostic.txt
```

**App shows `404` after install** — the platform may not have picked up the route yet. Wait a few
seconds and refresh, or confirm the Web UI was unpacked:

```bash
ls /usr/local/excalidraw/webui/index.html
```
